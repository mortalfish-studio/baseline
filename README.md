# Baseline

One person's Omarchy system, after *Blade Runner 2049* and rain-soaked neon noir: a set of **looks** (themes), the **Baseline** bar panel that drives everything, **Baseline Studio** for pictures and making looks, and voice control through **[OmaRelay](https://github.com/mortalfish-studio/omarelay)** (its own repo). Afterlight, sodium amber over smog-steel slate with a teal counterpoint, is the original look. More looks are shared in the **[catalog](https://github.com/mortalfish-studio/baseline-looks)**.

Open source under the MIT licence ([LICENSE](LICENSE)): take it, change it, make it yours.

**New here?** It was built on a Surface Laptop 7 (Snapdragon X Elite, ARM64) with a Razer Basilisk V3 mouse ([details](docs/install.md#built-on)); the mouse features won't work on other mice without changes. Start with [docs/install.md](docs/install.md) (prerequisites, with links to each app), read [what it changes on your system](docs/system-changes.md), set up the [Chrome add-on](docs/chrome-extension.md) for the music controls, and see [adapting it to your own coding and chat apps](docs/adapting.md). It's built for one person's day-to-day work and shared for fun: no support, plenty to tinker with. Changed your mind? `afterlight uninstall` puts your system back as it was before (see [Taking it off](docs/install.md#taking-it-off)).

This repo is the single source: everything it puts into the system is a link back here, and `afterlight repair` puts it back if an update knocks anything out (see Health below). The command and folder are still called `afterlight` for history's sake.

- `bin/afterlight`: the command behind it all (`afterlight --help`); linked into `~/.local/bin`
- `plugin/mortalfish.baseline/`: the Baseline bar widget, panel (System, Player, Status, Wallpapers, Look, Setup) and Studio; linked into `~/.config/omarchy/plugins`
- `colors.toml`, `hyprland.lua`, `night/`, `saver/`: the Afterlight look (Day, Night, Saver). Its pictures aren't published; add your own.
- `looks/<id>/`: the other built-in looks (Ultraviolet, Cobalt Rain, Neon Rose), each with `pictures.json`: links to its pictures, fetched by `afterlight pictures`
- `atmosphere.lua`: window atmosphere shared by every look and mode (dimming, blur, terminal transparency, slow "drift" animations), with the panel's tweaks laid over it
- `btop.theme`, `unlock.png`, `preview-unlock.png`: btop colours and the boot/unlock logo
- `system/`: everything installed outside the repo, each as a link: `bin/` (helpers), `hooks/` (boot, theme-set, post-update), `hypr/home.lua` (home workspaces, window rules, mouse buttons), `branding/screensaver.txt` (BASELINE / CELLS INTERLINKED), `shell/baseline.json` (the bar layout repair restores), `systemd/`, `wireplumber/`, `udev/`, `chrome/` (the autoplay policy, copied with sudo) and `plugin-patches/`

## Install on a new machine

On a fresh Omarchy install (no GitHub account needed):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/mortalfish-studio/baseline/main/install.sh)
```

`install.sh` fetches Baseline into `~/Projects/baseline` and OmaRelay into `~/Projects/omarelay`, then:

- takes a **snapshot** of everything it's about to change (`~/.local/share/baseline-before/`), so `afterlight uninstall` can put it all back
- installs the packages Baseline needs (python, imagemagick, starship, openrgb, cava, aubio, libkeyfinder, …) and the apps it's built around, through Omarchy's own installers: T3 Code, Grok Bot, Superwhisper and Chrome (`--no-apps` to skip)
- with `--dotfiles=<owner/repo>`, restores your desktop settings from your own dotfiles backup: key bindings, input, window look, autostart, night light, menus, foot, default apps, Baseline's settings, liked music and your own pictures (never `hyprland.lua` or `monitors.lua`, which belong to each machine)
- installs Baseline's prompt (`system/starship.toml`)
- runs `afterlight repair`, which builds the rest from this repo: every link and hook, the bar (at the bottom, with Baseline and the plugin copies; copies are made afresh from Omarchy's originals plus the saved patches), Hyprland's home workspaces and mouse buttons, and the services
- sets the look (the one in your settings, else Afterlight, or `--look=<id>`), downloads the built-in looks' pictures from their original sites, installs OmaRelay, and adds the charge-limit rule and Chrome's autoplay policy (for the Deck's mixes) with sudo
- finishes with the health check

Run it again any time to bring a machine up to date; options are `--no-omarelay`, `--no-apps`, `--look=<id>` and `--dotfiles=<owner/repo>`.

## Taking it off

`afterlight uninstall` shows what it will do and asks first (`--dry-run` only shows it). It stops Baseline's services, removes its links, puts every file it replaced back from the snapshot, switches to the theme you had, and removes the charge-limit rule and the autoplay policy (asks for your password). Nothing is deleted: whatever it removes or replaces, your looks and settings included, is moved to `~/.local/share/baseline-removed-<time>/`. Packages it added stay unless you pass `--packages`; apps it installed are listed with the Omarchy command that removes them. Without a snapshot (a machine set up before snapshots existed) it falls back to Omarchy's own defaults for the bar, prompt and screensaver.

## Health: check and repair

`afterlight check` lists every part Baseline puts into the system; `afterlight repair` puts back whatever is missing or changed. Baseline > Setup > Health shows the same, with Repair and Check again buttons.

- **Links & hooks**: the command and helpers, the plugin, `home.lua`, the three hooks, the systemd units, the WirePlumber rule, the screensaver text, and every look's themes in `~/.config/omarchy/themes/`. A real file found where a link should be is kept as `.bak-<time>`.
- **Desktop**: `hyprland.lua` still requires `hypr.home`, the coding and chat apps' workspace rules (`~/.config/hypr/baseline_apps.lua`) match Setup → Apps, the mouse bindings exist, and Hyprland reports no config errors.
- **Bar & plugin copies**: `shell.json`'s bar layout, plugins and disabled plugins match `system/shell/baseline.json` (a backup is taken before it's put back). The plugin copies get their changes re-applied to Omarchy's new versions. Changed the bar on purpose? **Keep this bar** (`afterlight repair --keep-bar`) saves it as the new reference.
- **Services**: the mouse daemon, the morning check and the day/night timer.
- **Look in other apps**: the starship prompt palette, T3 Code's neon layer and Chrome's colour match the current look.
- **OmaRelay** (under services): its installed copy matches its checkout (`install.py --check`); repair reinstalls it. **Looks from the catalog** (under look): any you've added are present; repair fetches them again. **Pictures for the built-in looks**: repair downloads any that are missing.
- **System (password)**: the charge-limit udev rule, Chrome's autoplay policy for the Deck's mixes, and OpenRGB. These need sudo, so **Repair system parts** (`afterlight repair --system`) runs them in a terminal where sudo can ask.

The Status tab's **Baseline** card shows new changes on GitHub (checked at most every six hours; **Update** runs `afterlight update`: pull Baseline and OmaRelay, reinstall OmaRelay, repair, restart the shell) or parts needing repair.

`system/hooks/baseline-repair` runs `afterlight repair --quiet` after every `omarchy update`; it sends a Baseline notification only when something was put back or still needs you. Results land in `~/.local/state/afterlight/health.json`.

## Modes

- **Day**, **Night** and **Saver** are three themes. `afterlight mode day|night|saver|toggle|auto` switches; the menu has Night Mode and Saver Mode entries.
- `afterlight-mode.timer` runs `afterlight mode auto` at the schedule's times (07:00 and 20:00 by default). A Saver picked by hand stays until it's left by hand.
- Saver turns the screen down, warms it, picks the power-saver profile and a solid bar, and puts all four back when it ends.

## Settings

Everything the panel changes is in `~/.config/omarchy/afterlight/settings.json`. Night wallpapers are darkened copies made from the originals into `~/.config/omarchy/backgrounds/afterlight-2049-night/` (Saver's into `-saver/`); added wallpapers go in `~/.config/omarchy/backgrounds/afterlight-2049/`.

Live copy: `~/.config/omarchy/themes/afterlight-2049` is a link to this repo, so edits here apply on the next `omarchy theme set "Afterlight 2049"`. Keep it a symlink: Omarchy strips `*.lua` from a theme folder that holds `.git` directly.

No pictures are kept in this repo. The built-in looks link to theirs (Wallhaven pages, with the uploader's credit) and `afterlight pictures` downloads them for your own desktop; their rights stay with their creators.

## Copies of Omarchy plugins

Some built-in plugins are copied into `~/.config/omarchy/plugins/` and changed: `mortalfish.osd` (popups near the top), `mortalfish.notifications` (which apps may pop up) and `mortalfish.workspaces` (workspace names). Each copy's changes are kept as a patch in `system/plugin-patches/`.

- `afterlight plugins status`: has Omarchy changed any of the originals?
- `afterlight plugins save`: record the copies' current changes (the daily dotfiles sync does this).
- `afterlight plugins restore`: after an update, take Omarchy's new version, re-apply our changes, and make sure the shell uses our copies. If a patch no longer fits, the old copy stays in use and Baseline sends a notification.

The repair (above) runs the restore after every `omarchy update`.

## Looks

A look is a whole colour scheme with its own wallpapers, in Day, Night and Saver alike: Afterlight (the original, at the top of this repo), Ultraviolet, Cobalt Rain and Neon Rose (`looks/<id>/`). Pick one in Baseline > Look, or `afterlight look set <id>` / `next` / `previous`.

A look's folder holds `look.json` (name, tagline, order), `colors.toml` (its Day palette), and `backgrounds/` (its own pictures, not tracked by git; anything dropped in there joins that look's library). The built-in looks are part of Baseline and read-only; looks you make in the Studio are yours, in `~/.local/share/baseline/mine/<id>/`. `afterlight look build <id>` writes its Night and Saver palettes and each mode's `hyprland.lua` from the Day palette, and links the three themes into `~/.config/omarchy/themes/` as `afterlight-<id>`, `-night` and `-saver`. Each look remembers which pictures you've ticked for Day and Night; wallpapers you add yourself are shared by all looks.

### Backing up and sharing looks

- **Your looks** live in `~/.local/share/baseline/mine/`, outside this repo. To back them up, set a backup command (`afterlight set backup.command '"~/Projects/dotfiles/sync.sh"'`, for example): saving or deleting a look runs it in the background, with the reason in `BASELINE_BACKUP_REASON`. `afterlight looks backup` runs it by hand.
- **Where pictures came from**: adding a picture from a link records its page and direct image link (`~/.config/omarchy/afterlight/sources.json`, synced with the dotfiles); a Wallhaven page link (`wallhaven.cc/w/<id>`) fetches its picture and keeps the uploader's credit and original source. The built-in looks list theirs in `looks/<id>/pictures.json`.
- **The public catalog**: [mortalfish-studio/baseline-looks](https://github.com/mortalfish-studio/baseline-looks) holds shared looks as data only: `look.json`, the palette, and picture *links* with credit (never the images). Studio → Browse lists it; **Add** checks each look (known colour keys and `#rrggbb` values only, plain short text, https links to Wallhaven, Unsplash or Wikimedia, no stock photos, at most eight pictures), writes its palette and window files locally, and can fetch its pictures from their sites (size-capped, no redirects, kept only if they really are images). Added looks live in `~/.local/share/baseline/looks/` as `c-<id>`, are remembered in settings, and come back on a new machine through repair.
- **Sharing**: Studio → Looks → **Share…** shows exactly what would go out, then opens a pull request on the catalog (`afterlight share <look> --preview`, then `--author=<handle> --include=<picture ids>`). Commits use your GitHub no-reply address. The catalog's own check (`tools/validate.py`) runs on every pull request, and nothing appears until it's merged.

### Chrome and T3 Code

Each look's theme folders carry a `chromium.theme` with the mode's accent (written by `afterlight look install`), so Omarchy seeds Chrome's frame, tabs and highlights from the look's own colour instead of its background; light or dark still follows the system. `system/hooks/baseline-theme` (a theme-set hook) runs `afterlight t3-neon`, which adds a small neon layer in the look's colours to the T3 Code theme Omarchy writes: a gradient under the chat header, a glow round the composer while typing, accent edges on your messages and the selected thread.

### Terminal prompt

The theme-set hook also runs `afterlight prompt`, which writes a `[palettes.baseline]` block (accent, highlight, alert, dim) into `~/.config/starship.toml` from the current theme. The prompt's folder and `◇` use the accent, git uses the highlight, and a failed command's `◆` uses red. Omarchy retints foot's own 16 colours.

## Music

The Player tab drives three services in Chrome, through the [Chrome add-on](docs/chrome-extension.md): **Beatport** (Top 100 charts and your playlists), and **YouTube Music** or **Apple Music**. *Find music* has a switch between those two: search songs, albums and artists and play one in that service's window without leaving what you're doing. On Apple Music a song plays within its album, so the album carries on after it, and an artist plays their top songs. The service picked there is also where OmaRelay's "play …" looks when it isn't a Beatport chart or playlist (`afterlight set music.service ytmusic|applemusic`); naming one always wins: "play Rumours on Apple Music". Apple Music is searched with Apple's public catalogue (`afterlight applemusic search …`), in your Apple Music account's own country (the player says which, so a song from another country's catalogue doesn't turn up; before it's known, your region's), and a song saved with another country's catalogue number is found again by title and artist when it won't play and played through Apple's own player in the page, so you need to be signed in there.

**Nothing plays on a guess.** "Play …" starts something only when the best match is clearly what you asked for: the title you said, and the artist when you said one. A mood or anything vaguer ("a sunset playlist for the kitchen") plays nothing and opens the Player tab on suggestions: the closest matches straight away, then about ten seconds later ideas from Grok's fast model (`grok-4.7-build-fast`, all tools off), each found on the same service so a tap plays it, plus searches to try. *Ask Grok for ideas* under the search box does the same for anything you type.

### What it needs

Baseline's music side is built around one setup (Chrome, Apple Music, Sonos, Grok), but the pieces stand apart: without one, the parts that need it say so and the rest carries on. To build on it with other services, these are the places to swap:

| Part | Needs | Without it |
|---|---|---|
| The Deck: the set, soft changes, the stage, the minimap, saving sets, the recap | Chrome with the [add-on](docs/chrome-extension.md), and YouTube Music or Apple Music signed in (Beatport too, if you like) | nothing plays; the add-on is the only way in |
| Apple Music on the laptop | an Apple Music subscription, signed in at music.apple.com | use YouTube Music; songs play in the same set |
| Guests' requests | Apple Music (guests search Apple's public catalogue), `qrencode` for the QR code | no requests; without `qrencode` the link shows instead of a code |
| Build a set, Fill, Auto-DJ, songs' energy | an agent's command line: [Grok](https://x.ai) (`grok`), Claude (`claude`) or Codex (`codex`), signed in | those say they need an agent; the set is yours to arrange by hand |
| Tempo and key | the Beatport window open; else measured from Apple's preview (`aubio`, `libkeyfinder` and `g++`, which builds the small key finder once); else an agent searching the web | songs show without them, and shaping by tempo or key has less to go on |
| Sonos rooms | Sonos speakers on the network, with Apple Music linked in the Sonos app; Send to Sonos also needs the Sonos MCP | the Deck plays on the laptop |
| Dedications read aloud | `afterlight voice install` (Kokoro, offline, about 350 MB) | dedications show on the stage without a voice |
| The Skyline equalizer | `cava` | a made-up pulse moves with the music instead |

The swap points in `bin/afterlight.py`: `deck_play_laptop` (starting a song in its app), `deck_status` (where it is), `deck_app_volume` (fades), `am_lookup`/`am_songs` (the catalogue guests and Auto-DJ search), `grok_ideas` and `grok_json` (anything Grok answers), and `sonos_call` (rooms).

### The Deck

The Deck has a workspace of its own, **7 · deck** (Super+7), where it fills the screen and is always there. *Open the Deck* in the Player tab, **Super+Alt+D** (or `omarchy-shell mortalfish.baseline deck`) pops it up over whatever you're doing instead; Escape, *Back to Deck*, or switching workspace sends it home. `omarchy-shell mortalfish.baseline deckView stage|requests|autodj|mix|set` opens it on the stage, the Requests card, the Auto-DJ panel, the Mix card, or none of them. It's a set of songs you arrange by hand, from YouTube Music, Apple Music and Beatport together. Rather not keep it open: `afterlight set deck.home false`.

- **Mixing services**: songs from all three sit in one set. On the laptop each plays in its own app (the YouTube Music or Apple Music window, the Beatport app); when one ends the next starts in its app, the old one fading out over its last few seconds (YouTube Music and Apple Music; Beatport's player has no volume Baseline can reach, so it stops at the end instead), and switching apps mid-song (Next, Back, playing another) pauses the one before, so only one ever plays (the next one starts first, then the last is quietened, so there's no gap). Changes are soft: **Next**, **Back** and ▶ on a song fade the song down over a second or so and bring the next up from quiet, **Pause** fades out before it stops and **Play** brings it back up, rather than hard cuts (on YouTube Music and Apple Music; a Sonos room and Beatport change straight away; `afterlight deck soft-skip off` for hard cuts). A song its app won't play (gone from Apple Music, or not in your country) doesn't leave the Deck sitting silent: a message says it was skipped, it shows crossed out under the set for a minute, and the next one starts; after three in a row the Deck stops and says so. Chrome won't let a page start sound until you've clicked in it once, so the first Beatport song after Chrome starts may need one click on Play in the Beatport window; the Deck says so when it does. In a Sonos room the whole set plays from Apple Music: YouTube Music and Beatport songs are looked up there by title and artist, and one Apple Music doesn't have is skipped in that room. Each song says which service it's from, and where it came from (the playlist or album, the brief Grok built it from, *Fill*).
- **Beatport** in the crate searches Beatport's tracks (each with its key, tempo and length) and your Beatport playlists (read in a background tab of the Beatport app, then each track's page, so a long one takes a little while). Build a set and Fill look on whichever service the crate shows. Tempo and key for the other services also come from Beatport, while its window is open.
- **Shape** reorders the set by its details, around pinned songs: *Shuffle*, *Party arc* (ease in, peak about two thirds through, wind down), *Harmonic mix* (each song in a key that mixes with the one before, close in tempo), *Smooth tempo*, *Tempo, slow to fast*, *Energy, calm to peak*. Songs without the detail stay at the end. **Fix the bumps** keeps your order and only moves the ◆ songs, each to wherever it sits best, while that makes the set smoother, and only within its part of the set (the songs around it from the same build, in the same chapter), so the night's shape and a set built after another stay as they are. It takes a moment even on a long set. Undo takes it back.
- **Find music** on the left (the YouTube Music / Apple Music / Beatport switch): songs, albums and playlists, with your own playlists first. ▶ plays it now (an album or playlist plays from its first song, the rest following), + adds it to the set; or drag it into the set, onto the cover, or onto a room. Tap an album or playlist (or 󰁔) to open it and pick songs out of it one by one, each remembering where it came from; its header still plays, mixes in or adds the lot. So it doubles as a plain player: search for a playlist you already have and press ▶. Apple Music playlists (yours and Apple's) are found through Apple's own player in the Apple Music window, so that needs to be open and signed in.
- **Arrange the set**: drag songs up and down, pin one (📌) to keep it in place when you shuffle, remove one, or drag a song from *Played* (󰋚 in the header) back in.
- **The Bloom**: press and hold a song you found (or tap one while something's playing) and four petals open around its cover: **Now** (up, plays it straight away), **Next** (right, straight after this song), **Later** (down, the end of the set) and **Mix in** (left, an album or playlist's songs scattered through the set, leaving what's next alone). Flick toward a petal without letting go, or let go and tap one; the cover flies to where it landed. Tap or hold a song in the set (without moving) for the same petals, with *Remove* on the left; move it and it drags instead, even if the petals had opened, so reordering never gets caught by them. Escape or a tap outside closes it.
- **The set in time**: the list is what's coming (*Played* opens above it from 󰋚 in the header: tap a song to play it again, or drag it back in; the playing song is the big one at the top) (the playing song is the big one at the top, with its progress and what's left), each with the time it starts. The header says how many songs, how long and when the set ends. Songs carry their key (on the DJ wheel, like *8A*) and tempo from Beatport, and an energy from Grok; the set reads in steady columns, so nothing shifts with a song's name: the song (title, then its service, artist and why it's there; long names stop short), its **key**, its **BPM**, when it **starts**, and play, pin and remove, which show on hover (a pinned song keeps its pin lit). Each song's key and tempo read against the song before it (the playing one, for the next). The list stays calm: hover a song and its key or BPM turns amber if it doesn't flow: the key when it clashes (it mixes when it's the same, one step round the wheel, or its relative), the BPM when the tempo jumps more than 8% (half or double time counts as flowing), and it says why in plain words under its title (*tempo jumps 139 → 87*, *key 1A clashes with 11B*, or *same artist again*); one that flows shows where it came from. When some songs don't flow, the header offers **Smooth it out (N bumps)**: one tap reorders the set so each song follows on from the one before (the same as *Fix bumps* in Shape; pinned songs stay, and *Undo* puts it back). Like Shape, it's hidden while the Deck is locked, and once the set is as smooth as it goes (the bumps left would change its shape) it goes away until the set changes. The playing song shows its own key and tempo under its title, to read the next ones against. Songs a *Shape* has already placed aren't flagged, only ones added since; after *Smooth it out* the bumps left still show, because they're real. **Undo** takes back what you did, one thing at a time: songs that came in since (Auto-DJ's, the song *Back* put back) stay where they are, pins made since stay, and a song taken from what's played goes back there. Auto-DJ's own additions and tidying aren't on it, and nor is a change that changed nothing. (Tempo and key need the Beatport window open; the details fill in on their own over a minute or so.)
- **Getting around**: the minimap down the right is always there and is the whole set at once (a short set gets a dot on each song, so even three songs have a shape, and the box for the part you can see only shows once the set is longer than the list), each song a tick coloured by its energy, the energy as a line, amber marks where something doesn't sit well, and a box for the part you can see; tap or drag it to go there. Scrolled away, **↑ Now** and **↓ End** float over the list. Keys: Home or N for what's playing, End for the end, / to find a song in the set, W for the cover wall, Ctrl+Z to undo, Ctrl+A to pick them all, Delete to remove what's picked. Drag a song to the list's top or bottom edge and it scrolls.
- **Chapters**: a built set comes in chapters (*Warm up*, *Build*, *Peak*, *Wind down*). Hover a song's number and press § to start one there; tap a chapter's name to rename it, its arrow to fold it, drag its header to move the whole chapter, × to join it to the one before.
- **Several at once**: Ctrl-click songs (Shift-click for a run) and the header offers Now, Next, Later and Remove for all of them; the Bloom on a picked song moves them all.
- **Undo** takes back the last change to the set (the last 30). **Save** keeps it under a name: what's to come, what's been played (the night so far; *Played* keeps up to 300 songs), or the whole night. Save opens petals for where it goes, like the Bloom: *Here* keeps it in the Deck; **Apple Music**, **YouTube Music** or **Beatport** instead makes a new private playlist in your account there, of the songs that service has (each looked up by title and artist; ones it doesn't have are left out, and a message says how many made it). A saved set's 󰈝 on hover opens the same petals. Before you search, the crate shows your saved sets, each with its length, the date, its services and where its songs came from (▶ plays one in place of the set, + adds it), and then your own playlists.
- **Mixing** (*Mix* opens the Mix card): when a Beatport song is followed by another, the Deck mixes one into the next the way a DJ would, on the laptop and in a Sonos room hearing the live stream. Every song has two halves to it, the **bass** (kick and bass line) and the **melody** (everything above), and each style moves them differently with EQ, filters and level:
  - **Bass swap**: both songs play in time, the new one's top creeping in with its bass held right down; on a downbeat halfway the bass swaps over (never two kicks fighting), and the old song's top fades away.
  - **Beat first**: the new song's drums and bass take over a quarter of the way in, under the old song's melody; then the new melody rises as the old one fades out.
  - **Smooth**: a long, even crossfade, the bass handed over gently through the middle.
  - **Filter**: the old song thins out through a rising, slightly resonant high-pass (the way a DJ mixer's filter sings) while the new one comes up under it; the bass swaps halfway.
  - **Cut**: a 4-bar low-pass fade over the old song, its last bar fed into an echo that rings on in time after it's gone, and the new one lands on the downbeat.

  **Auto** (the default) picks per seam: a bass swap, a filter when the keys clash, a cut when the tempos are too far apart or the beat can't be heard clearly. The Mix card draws the chosen style (hover a style to see its drawing): two lanes, bass and melody, with the song going out and the one coming in, and the moment the bass changes hands. **Length** is *Auto* (32 bars between two extended mixes, otherwise 16), 8, 16 or 32 bars. Between two Beatport songs the set shows the seam (*BEAT FIRST · 32 BARS*); tap it to pick a style for that one song (each style in turn, then back to the Deck's choice; a dot marks a pick). About two and a half minutes before the end, the Deck listens to both songs for 16 seconds each to find the real tempo and where the beats fall (Beatport's listed tempo is often rounded: a "125" played at 123), cues the next song silently in a second, hidden Beatport window, starts the mix on a 16-bar phrase with its tempo matched (the key held) and its beats lined up, and shapes both on one clock. Like a DJ's gain knob, it evens out their levels (half the difference it hears, at most 3 dB), and through a bass swap the mids trade a little so two songs never come out louder than one. Ten seconds in, it listens to both again and compares their kicks; if they've drifted apart by more than 6 ms it nudges the new one back into line. Under the song a line says *Beat first into … in 0:24*, then *Bringing in the beat of … · Bar 8 of 32*, beside the mix drawn small with a playhead running through it; the progress bar marks the mix and its takeover, the seam lights up, and the stage shows it too. After the mix the new song eases back to its own tempo over 32 bars. **Mix now** (by Next, while a Beatport song plays with another next) mixes in at the next 8-bar phrase instead of near the end, about a minute later once it has heard both. The set moves on as the new song takes over; Pause or Next stops the mix at once. Under the style, **Other songs** is how songs that aren't mixed follow each other: *Crossfade* (on the laptop the song fades over its last seconds with the next coming in under it; in a Sonos room, the room's own crossfade) or *Straight on*; and on the laptop, *Next, Back, Pause* either fade quickly or act at once. Fill and Shape sit with the set's own tools above it. What it heard and planned goes in `deck-mix.log`. `afterlight deck mixes on|off|now`, `afterlight deck crossfade on|off`, `afterlight deck mixes style <swap|beat|smooth|filter|cut|auto>`, `afterlight deck mixes bars <0|8|16|32>`, `afterlight deck mixes pick <song> <style|auto>`.
- **The heads-up**: in the last 20 seconds of a song the next one slides in, with *Skip it* and *Later*.
- **Sleep** (󰒲) stops the music after 15, 30 or 60 minutes or at the end of the song; tap again to cycle, back to off. How one song goes into the next (crossfade or straight on, and on the laptop whether Next, Back and Pause fade) is in the **Mix** card, with the Beatport mixes. 󰒮 goes back.
- **Looking after the night**: if the music stops by itself while the Deck says it's playing (the Apple Music or YouTube Music window closed, the network dropped, you were signed out), the Deck notices within about ten seconds and starts the song again where it was, reopening its window. If that doesn't take within half a minute, it stops and says why, under the song and as a tag on the stage, and Play tries again. Pause it in the app itself and the Deck follows (paused). A fade cut off halfway (a restart, a crash) never leaves the music stuck quiet: the real level is put back. Headphones coming out pause the Deck softly, so the song doesn't carry on out loud from the speaker; Play carries on. On battery, the Deck warns at 20% and again at 10% (the warning shows on the Deck and the stage until it's plugged in). In the last half minute of a song the stage counts down to the next one, and while Auto-DJ is heading somewhere the stage says where. With two songs or fewer left and Auto-DJ off, a line under the set says so, with *Fill* and *Turn on Auto-DJ*. When the set runs out, the stage says *That's the set.* over the last song's cover, with **Fill** and **Auto-DJ** to find more from tonight and play on. With Apple Music songs coming up and nothing playing, opening the Deck gets the Apple Music window ready in the background (on its own workspace, without taking you there; at most every ten minutes), so the first song starts at once; when a song needs the window and it isn't open, it opens the same quiet way. A song that came without a cover gets Apple's, found by title and artist.
- **The cover wall** (󰕰): the set as big covers with their start times, for across the room, with what's playing first and bigger, its progress under it. And behind it all, the playing song's cover glows softly in its own colours.
- **Stage** (󰐯, or P): for a party. The whole window becomes the playing song: the cover, its name in big type sliding in as each song starts, its progress, the sound across the bottom, the time, and the next three songs with when each starts, all in the cover's colours. Taps do nothing there; Esc or P goes back.
- **Guests' requests** (󰄜 *Requests*, then *Open requests*): a page on your home network, with a QR code to scan (on the stage too, bottom right). The first time, a guest says who they are: a name, and a selfie if they like (taken on the phone, kept small, on this laptop only); after that their phone remembers them, next party too. They search Apple Music there (it plays on the laptop and in every Sonos room), see what's playing and next, add up to five songs while they keep searching, and send them together. Their name and face come with each request, in the crate (newest first; it scrolls after four) and in the popup. Their phone lists what they've asked for and what became of it (waiting, in the set and about when, playing now, played, or not this time), marks songs they've already asked for or that are already in the set, and tells them if they ask twice. When a guest's song is next, their phone says so (and about when) with a little buzz; when it comes on, the stage gives them a shout-out with their face, and their phone lights up and buzzes again (the buzz is on Android; iPhones don't let web pages vibrate). The phone's now-playing card has a bar that runs with the song, covers fade in as they load, and sent songs fly off the tray. While a dedication is read, the stage hushes and the guest's face takes it over, sound rippling out from it, their words typing out as the voice says them. A new request slides in under the song's name for a few seconds (face, cover, and whether it has a dedication) while the stage blurs and dims behind it. The cover (rounded, like the one in the Deck) glows with the bass, and when the song changes the next cover dissolves in over it, while the songs coming up slide along one after another. Each request's tempo, key and length are looked up as it arrives, so it's ready to fit in, and when one with a dedication is next its spoken clip is made ahead, so it's ready to say (with *Add them by itself*, it goes in once they're known). Closing and opening requests again the same night keeps the same link and QR code. Guests can add a **dedication** to what they send ("for Jess's birthday!"): it shows on the request and on the stage when the song plays, and the guest's face comes up big on the corner of the cover. On the phone, *+ Dedication* opens a roomy box to write it in (up to 120 characters), and closed it shows what you wrote. With **Read dedications** on (in the Requests card, once the voice is installed with `afterlight voice install`), a voice says it too: "A request from Sam. For Jess's birthday. Here's Lady, by Modjo." On the laptop it talks over the song's intro while the music dips; in a Sonos room it plays as the song before ends, and the room goes straight into the requested song (skip to it by hand and the room says it first, then starts the song from the top). Step through the voices under the switch with ‹ › and each says hello: *Michael* (warm and relaxed, our pick, and the default), *Fenrir*, *Heart*, *Emma*, *George*, *Puck*, and *Robot* if you've installed the first, plainer voice too (`afterlight voice install robot`). The voices are [Kokoro](https://github.com/thewh1teagle/kokoro-onnx) (Robot is [Piper](https://github.com/OHF-Voice/piper1-gpl)); they run on the laptop, offline, and nothing is sent anywhere. On their phone they can 👍 or 👎 what's playing (the stage shows the count, and Auto-DJ leans towards what the room liked and away from what it didn't), and open *Tonight's songs*: every song that played (theirs starred), each with links to open it in Apple Music, Spotify or YouTube Music, and *Share list* or *Download* to keep it (a text file with the Apple Music links; free tools like TuneMyMusic turn it into a playlist). A dedication with swearing or a slur is turned away on the phone, since it's shown and read out to everyone. **Last call** (in the Requests card: 15 or 30 minutes, or now) tells the phones when requests close, then closes them; *Reopen* takes it back. When requests close, the voice says thank you, the phones show *Thanks for the music!* with tonight's songs to save, and the stage shows the **recap**: tonight's covers drifting behind, the songs, hours, requests and dedications counting up, the most loved song, the crowd's top DJs (the top one glowing), and the code to save tonight's songs. *Recap* in the Requests card (or `afterlight deck recap`) shows it any time; a tap closes it. **Save tonight to Apple Music** on the recap makes a new playlist of the night's songs in your library (only when you press it; `afterlight deck export applemusic <name> --tonight`). While requests are open the laptop stays awake (no lock or sleep), and goes back to how it was when they close. **Check everything** in the Requests card (or `afterlight deck ready`) looks over the party before it starts (the results put themselves away after 20 seconds, or tap it again): the requests page answers, phones can reach it past the firewall, the QR code, the voice, the Sonos room, staying awake, and guests left from before. With the voice on, it's said out loud too ("Last call for requests! You've got 15 minutes…", and a thank-you when they close), while the stage shows the QR code big; until then a tag by the stage's clock says when requests close. The Requests card also shows **tonight's guests**, with their faces and how many of their asks got played (*4/9*; past two rows, a *+N* shows the rest). Hover a face (or press and hold it) for ✕ to drop that guest and their waiting requests; *Start fresh* (tap twice) forgets every guest, their selfies and waiting requests, and their phones ask who they are next time, and the top five sit along the top of the stage, bobbing with the music (whoever has had the most played glows softly). The page is in your current look's colours. While requests are open the QR code sits at the top of the crate (in the header instead while the crate is folded away), and tapping any QR code shows it big in the middle of the Deck, for a phone to focus on. Requests wait at the top of the crate (and on the stage, top right, so you can take them without leaving it; 󰆴 above them, tapped twice, turns them all down): ◆ **fits one in** where it fits best in the next few songs (key, tempo, a different artist), 󰒭 next, 󰐒 at the end, 󰅖 turn it down. Or *Add them by itself*, and each goes straight in where it fits. Each phone can send once every 20 seconds and have eight waiting; `afterlight deck guests forget` forgets every guest and their photos; the page only searches and asks (nothing else in the Deck can be reached from it), its link has a secret in it, and it closes itself after 8 hours or with *Close requests*. Phones reach it only if the firewall lets them: see [system changes](docs/system-changes.md#what-needs-your-password). The QR code needs `qrencode` (without it, the link shows instead).
- **Lock** (󰍁): for when guests are near the laptop. Clear, remove, undo, Shape and Fill go away, and so does everything that throws away guests' things: turning a request down, clearing requests, dropping a guest, *Start fresh*, closing requests and last call, and the request switches and voice. Playing, skipping, adding and putting requests in the set still work. Hold *Locked* for a second to open it again.
- **Played, by the hour**: opened (󰋚 in the set's header), *Played* marks where each hour starts, so you can find what played around 11.
- **Auto-DJ** says in the set's header when it will next add songs.
- **Tempo and key** come from Beatport first, exact. For songs it doesn't have, they're measured from the song's 30-second preview in Apple's public catalogue: aubio finds the beats and libkeyfinder (the key finder Mixxx uses) the key. Tested against Beatport on 31 songs, a measured tempo was within 1 BPM whenever the beat held steady (it only counts then), and the key was exact for 58% and a mixable neighbour on the Camelot wheel for another 26%, where an agent searching the web managed 39% and 19%. So a measured key always beats the web's. Only a tempo still missing (an unsteady beat, no preview) goes to the quick agent on the web, a few songs to a question, once each.
- **The crate** (*Build a set* and the search) folds away to a thin rail with 󰅁, giving what's playing the room; 󰅂, 󰍉 or ✦ on the rail opens it again. It stays as you left it (`deck.crate`). *Build a set* itself stays one line until you tap it (or pick a song to grow from). Rest on any icon for a word on what it does; the rooms say *Tap or drop a song* only while you hover or drag.
- **The Skyline**, next to the song, is the Deck's equalizer in the look's colours. On the laptop it shows the real sound ([cava](https://github.com/karlstav/cava) reading PipeWire); in a Sonos room, where the sound never passes through the laptop, it moves with the music instead. It's always there: if the real sound goes too quiet to read, or cava stops, the made-up pulse takes over (and cava is started again) until the sound comes back; paused, it rests as a slow swell. The little peak caps hang for a beat, then drop back onto their bars, picking up speed as they fall. Long titles show their main part large and what's in brackets (*Original Score*, *feat. …*) on a line below.
- **Build a set** from a brief: say what the party is (a theme, a mood, who's coming, artists to lean on), pick a length (30 minutes to 3 hours) or a number of songs (10, 20 or 30), and the quick agent curates it in play order: it eases in, builds, peaks about two thirds of the way and winds down, starting from the song that's playing. By length, it's fitted to the songs' real lengths (within half a song: songs come out of the middle, so the opening and the wind-down stay; when it's short, more go in before the wind-down). With songs in the set already, the new ones go **up next**, **after the set** (growing from its last song) or **in place of it**; none is a song already there. Each song carries a few words on its job in the set. **Grow it from a song**: ✦ on a song you found makes it the seed (it shows in the Build card); Build then opens with that song and grows the set from its sound, tempo and key, and the brief becomes optional. The card says which agent will do it and about how long it takes, from how long its answers have taken. **Fill** adds five more that fit what's already there, and **Fill to** (under the set) tops it up to 1, 2 or 3 hours. A message says when the songs land.
- **Auto-DJ** (∞): tap it for its panel: *On* / *Off*, the **Direction** it takes the night, **Take it towards** somewhere new, and whether it tidies its songs. While it's finding songs (about a minute) the button reads *Auto-DJ…* and the panel and the set's header say what it's looking for; the destination you picked stays lit. While it's on, a quiet row under the last song says it'll line up more (or what it's finding). While it's on and the set gets down to three songs, Grok adds songs that carry the night on from the last one. It weighs the newest songs most (the last six, with their tempo, key and energy; the rest of tonight is background), and the next song has to sit near the one it follows: within about 8% in tempo and in a key that mixes. Grok guesses each suggestion's tempo, key and energy; ones too far off in tempo are dropped, and the rest go in an order that mixes, each nearest the one before. Grok's guesses can be off, so once the songs' real tempo and key are in (a minute or so; four at most) Auto-DJ tidies them: *Fix bumps*, but only its own songs move, never the next one, yours or pinned ones (a destination's bridge keeps its order). *Auto-DJ tidies its songs* in its panel turns that off (`afterlight deck autodj tidy off`). A search still running when Auto-DJ is turned off, or when the set is replaced (Build, Clear, loading a saved set over it), is dropped when it finishes, so nothing turns up uninvited. Guests' requests count as what the room wants, 👍 and 👎 lean it towards or away, and a song you skip within 45 seconds counts as "not that". The **Direction**: *Follow the night* (the default), *Arc* (the night's curve by the clock: ease in, peak, wind down), *Build energy*, *Raise tempo* (a few BPM a song), *In key*, *Steady tempo*; the set's header says which, and turning Auto-DJ off forgets it. Picking one of those in **Shape** also reorders the set that way and sets the direction to match. It can also **take the night somewhere new**: *Take it towards* a sound you type ("90s house", "something for a sunset") or a preset (*Wind down*, *Peak time*, *Throwbacks*, *Deep house*, *Latin heat*, *Chill out*), or `afterlight deck autodj toward <words>`. Auto-DJ's own queued picks after the next song make way (yours and guests' requests stay), and six songs bridge from where the night is to there, each a step closer; then it stays there. The header shows the way (*heading to deep house, 3/6*); *Stop heading there* (or `… toward off`) lets it follow the night again. Nothing already played or in the set, and not the same artists straight away. It tops up at most every three minutes, all night. It works from a single song too: play one and turn Auto-DJ on, or ∞ on a seed in the Build card, which plays that song next and grows the set from it.
- **Dig deeper** (in *Build a set*): instead of one quick answer, three scouts dig at once from different angles (a crate digger for deeper cuts, a mixer for songs that blend, a crowd reader for the ones people sing along to). Their ideas are pooled, with a vote for each scout that named a song, and every one is looked up on your music service, so only real, playable songs go on. Then the judge picks and orders the set from what's left and says a word about it. If the judge doesn't answer in four minutes, the quick model stands in; if that fails too, the songs most scouts agreed on go in. It takes a few minutes, depending on the agents. The agents card shows how the last dig went: each scout's ideas, how many were found and how many made the set, and how long each took (`afterlight deck build <minutes> <brief> --deep`).
- **Agents**: the Deck's music questions (picking songs, building a set, Auto-DJ, tempo and key, energy) go to whichever agent you pick: Grok, Claude or Codex, each through its own command line, signed in as you set it up in Omarchy. Tap the line in the middle of the header for the agents card: one choice for **quick jobs** (a small, fast model), one for **scouts** (digging for songs) and one for the **judge** (weighing what the scouts found), with each model's record so far (questions asked, seconds on average, how many came back usable). While an agent works, that line becomes a soft waveform in the agent's colour (Grok white, Claude in the look's accent, Codex teal), with who's doing what and for how long underneath; it settles flat when they're done. Scouts can also be set to **Mix**, so each digs on a different agent. Each kind of job has a time budget (quick jobs 30 seconds, scouts a minute, the judge two): after two questions, an agent that averages over it, or answers usably less than 60% of the time, is marked slow or unreliable for that job. One question that took over twice the budget is enough to say slow. Mix then leaves it out (giving it another try after a week). Each agent runs on a subscription with a weekly allowance, and the quick, big models use the most of it, so speed only decides who's fit: a job you haven't picked an agent for goes to the fit one with the most of its week left (read from `omarchy agent account list`, every ten minutes), and one that's used 90% of its week sits out, from Mix too, unless every agent has. The agents card shows each one's week so far. If you picked an agent yourself, your choice stands, with a note in amber saying how long it takes and who'd be quicker. In *Dig deeper*, once all but one scout have answered, the last gets 45 seconds more before the set goes on without it. Sonos control stays with Grok. `afterlight deck agents` shows the choice, `afterlight deck agents use <fast|scout|judge> <grok|claude|codex|mix>` changes it, and `afterlight deck agents ask <tier> <words>` puts a question to it.
- **Play in** a room: tap the laptop or a Sonos room along the bottom, and the set moves there at the same second. It's the same room as the Player tab's Sonos card: picking one in either place picks it in both (and the volume keys follow), and picking Speaker or Headphones there brings the Deck back to the laptop. On the laptop, songs play one at a time in their own app and Baseline starts the next when one ends (start something else yourself and the Deck steps back). In a Sonos room a set can mix services, and each song plays the way its service allows. Apple Music songs go into the room's own queue (the next 30 at a time, topped up as it plays), so the speaker plays them gaplessly, and skipping on the speaker or in the Sonos app moves the Deck along too. Beatport and YouTube Music songs, which Sonos can't play itself, play in Chrome on the laptop into a silent output, and the room plays what the laptop plays as a live stream, like a radio station (the Sonos app shows the song's title). The laptop stays quiet, the room runs a few seconds behind it, and nothing is saved. At the end of a run of Apple Music songs the next streamed song starts on the laptop a few seconds early, so the room goes straight into it from its first beat (about two seconds between); after a streamed song, the room plays out its end and then its queue starts. Pause hushes the room at once. The laptop has to stay on and awake while it streams. Rooms reach the stream on port 8766: allow it once with `sudo ufw allow from 192.168.0.0/16 to any port 8766 proto tcp` (until then it borrows the requests page's port while requests are closed). `afterlight deck room-stream off` goes back to looking every song up on Apple Music, as before.
- **Volume**: a slider at the end of the controls sets the volume where the Deck plays: the Sonos room, or on the laptop its speaker or headphones (the icon shows which), with the same line on the Laptop tile (`afterlight deck volume 30`, or `+5` / `-5`; on the laptop it's the system's own volume, so the volume keys and the Deck stay in step).
- **Listen** (in a room): the equalizer can't hear a Sonos room, so it moves like music on its own; tap *Listen* above it and it hears the room through the laptop's microphone instead, read straight from PipeWire so it keeps up with the music (only levels, nothing is kept, and only while the Deck is on screen and playing in a room). Tap *Listening* to stop.

- **Rooms together**: once the Deck plays in a Sonos room, that room sits in a capsule with the others playing the same music, joined by a line. Drag another room into the capsule (or hover it and press 󰌹) to add it; it plays in step and joins no louder than the loudest room already playing. Drag a room out (or 󰌺) to take it out; if it led the group, the next room carries on with the queue. Each room in the capsule has its own volume line. **Everywhere** adds every free room: a room already playing something else, like the TV, is marked *In use* and left alone.

- **By voice** with [OmaRelay](https://github.com/mortalfish-studio/omarelay): “open the deck”, “play the deck in the kitchen”, “build a two hour set for a rooftop party”, “shape the deck by tempo”, “turn on auto DJ”, “save tonight as Friday”, “sleep in 30 minutes”, “add this song to the deck” (whatever an app is playing), “play Blue Monday next on the deck”, “build a set from this song”, “what's next on the deck?”.
- **Media keys** (play/pause, next, previous) drive the Deck while it plays or you've paused it, in whichever room; otherwise they work as before. Hovering the bar's music shows what's next on the Deck.

The same from a terminal: `afterlight deck state|add [--next|--play|--at <n>|--scatter]|move|remove <uid>…|place <now|next|end> <uid>…|chapter <uid> [name]|move-chapter <uid> <index>|undo|save <name>|sets|load <name> [--replace]|songs <service> <album or playlist json>|grab [--next]|find-add <words> [--next]|build-from-playing [minutes]|next-up|forget <name>|mine <service>|shape <arc|harmonic|smooth|tempo|energy>|autodj <on|off>|autodj from <service> <song json>|export <service> <name> [--played|--all|--saved|--tonight]|sleep <minutes|song|off>|crossfade <on|off>|pin|shuffle|clear|play|pause|next|previous|where <laptop|room id>|rooms|join <room id>|leave <room id>|everywhere|volume <0-100|+n|-n>|volume <room id|laptop> <0-100>|soft-skip <on|off>|fill [--to <minutes>] [--service <s>]|build <minutes, or songs with --songs> [brief] [--start <song>|--seed <song json>] [--replace|--after] [--deep] [--service <s>]`. `find-add` takes the artist you name over a cover act the service lists first, from the artist's own single or album if it has to.

## Sonos

When Sonos speakers answer on your network, the Player tab's output row gets a **Sonos** tile. Pick it, then a room (groups show as "Kitchen + Lounge"): the card shows what that room is playing, with its cover, play/pause and skip, and the volume slider, mute and the keyboard's volume keys now drive that room (`system/bin/baseline-volume`). Pick Speaker or Headphones to hand them back. The laptop's own sound isn't moved. While a room plays (picked here, or the Deck moved there), the laptop's player section is hidden, so the tab shows only what the room plays; it comes back with Speaker or Headphones. It all talks to the speakers directly on the local network (`afterlight sonos …`), so it's instant and needs no account; keep UPnP on in the Sonos app. Playing something by name goes through OmaRelay and the Grok agent: "play Bonobo on Sonos in the kitchen".

**Send to Sonos.** While the laptop plays something (YouTube Music, Apple Music, Beatport, YouTube), the Sonos card offers *Continue … in Kitchen*, and OmaRelay takes "send this to the kitchen". Sonos can't play a browser tab, so the Grok agent finds the same album on Apple Music in that room (linked in the Sonos app); then Baseline skips to the same song and second and pauses the laptop, which keeps playing until the room starts. It takes 15–45 seconds and needs the Sonos MCP set up as above (`afterlight sonos send [room]`). Sonos's agent tools can't play YouTube Music yet, so Apple Music is the bridge; Beatport isn't on Sonos at all.

A new song shows in the music popup at the top of the screen, with its cover (it waits a moment for the name to settle and the cover to arrive, and a cover that arrives late goes straight in). Sonos messages (sending, playing, a room switched) show there too, with the cover; the hover card shows where music is playing.
